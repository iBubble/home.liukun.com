# 付费节点代理集成说明

## 概述

已将付费订阅节点集成到主应用 `app.js` 中,所有外网访问(包括 Linux.do, GitHub, 其他订阅源)都会优先使用付费节点代理。

## 实现方案

### 1. 代理管理器
创建了 `premium_proxy_manager.js` 模块,负责:
- 加载付费节点
- 启动/停止 Clash 代理
- 提供代理配置信息

### 2. 修改的文件

#### app.js
- **引入模块**: 添加 `getPremiumProxyManager` 导入
- **修改 fetchWithProxy**: 优先使用付费节点代理
  - 首次尝试: 付费节点代理
  - 失败回退: 代理池节点
  - 最后回退: 直连
- **任务完成清理**: 在 `runAggregation` 的 `finally` 块中停止付费节点代理
- **Linux.do 导入**: 完成后也停止付费节点代理

### 3. 代理使用流程

```
开始获取节点
    ↓
检查付费节点是否可用
    ↓
启动付费节点代理 (端口 7940)
    ↓
使用付费节点访问外网
    ├─ Linux.do
    ├─ GitHub
    ├─ 其他订阅源
    └─ 所有需要代理的网站
    ↓
如果付费节点失败
    ↓
回退到代理池节点
    ↓
如果代理池也失败
    ↓
尝试直连
    ↓
获取完成
    ↓
停止付费节点代理
```

## 使用的端口

- **7890**: 主 Clash 验证端口
- **7891**: 代理池节点端口
- **7940**: 付费节点代理端口 (新增)

## 优势

1. **稳定性**: 付费节点质量高,连接稳定
2. **速度**: 专线节点速度快
3. **成功率**: 提高外网访问成功率
4. **自动回退**: 失败时自动切换到备用方案
5. **资源管理**: 任务完成后自动停止代理,节省资源

在日志中可以看到以下标识:
- `[代理]`: 付费节点代理管理器的日志
- `🚀 启动付费节点代理...`: 开始启动
- `✓ 使用付费节点代理`: 正在使用付费节点
- `🔄 付费节点失败,切换到代理池...`: 回退到备用方案
- `🛑 停止付费节点代理...`: 停止代理

## 配置要求

1. **付费节点文件**: `premium_nodes.json` 必须存在
   - 通过 `node premium_subscription_updater.js` 生成
   - 定时任务每6小时自动更新

2. **Clash 二进制**: `clash_bin/clash-linux-amd64` 必须存在

3. **Cookie 文件**: `linuxdo_cookie.txt` (用于 Linux.do 访问)

## 故障排查

### 问题1: 付费节点代理启动失败
**原因**: premium_nodes.json 不存在
**解决**: 
```bash
node premium_subscription_updater.js
```

### 问题2: 仍然使用代理池
**原因**: 付费节点代理启动失败或连接超时
**解决**: 
- 检查付费订阅是否有效
- 查看日志中的错误信息
- 手动测试: `node test_premium_nodes.js`

### 问题3: 代理未停止
**原因**: 进程异常退出
**解决**:
```bash
# 手动清理
pkill -f "app_proxy_config.yaml"
```

## 性能影响
