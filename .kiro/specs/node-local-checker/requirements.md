## 1. 项目概述

### 1.1 项目背景
开发一个本地节点检测工具，用于测试代理节点的可用性、延迟和IP纯净度，帮助用户筛选优质节点。

### 1.2 目标用户
- 需要测试代理节点质量的用户
- 需要筛选可用节点的用户
- 需要评估IP纯净度的用户

### 1.3 核心价值
- 真实检测：使用Clash核心进行真实代理测试
- IP纯净度分析：综合评估IP质量
- 智能管理：自动更新和数据持久化
- 优秀体验：科幻风格界面和流畅动画

## 2. 功能需求

### 2.1 节点导入功能

**需求描述**: 支持多种方式导入代理节点配置

**用户故事**:
- 作为用户，我希望能够从机场聚合器一键导入节点，以便快速获取最新节点
- 作为用户，我希望能够上传本地YAML文件，以便导入自定义节点配置

**验收标准**:
- [x] 支持从机场聚合器API一键导入
- [x] 支持上传本地YAML文件
- [x] 自动解析vless、vmess、trojan、ss、ssr、hysteria2等协议
- [x] 导入时自动去重（基于type+server+port+UUID/password）
- [x] 导入成功后显示节点数量

### 2.2 节点检测功能

**需求描述**: 使用Clash核心进行真实代理检测

**用户故事**:
- 作为用户，我希望能够检测节点的真实可用性，而不是简单的TCP连接测试
- 作为用户，我希望能够测量节点的延迟，以便选择最快的节点
- 作为用户，我希望能够并发检测多个节点，以便提高检测效率

**验收标准**:
- [x] 使用Clash核心进行真实代理测试
- [x] 测试被墙网站（Google）确保准确性
- [x] 支持10个节点并发检测
- [x] 精确测量延迟（毫秒级）
- [x] 显示检测进度条
- [x] 检测完成后自动按延迟排序

### 2.3 IP纯净度检测

**需求描述**: 检测代理节点的真实IP和纯净度评分

**用户故事**:
- 作为用户，我希望知道节点的真实IP地址
- 作为用户，我希望知道IP的类型（数据中心/住宅/移动）
- 作为用户，我希望知道IP的风险评分，以便判断IP质量

**验收标准**:
- [x] 获取节点的真实IP地址
- [x] 识别IP类型（数据中心/住宅/移动）
- [x] 计算风险评分（0-100分）
- [x] 显示地理位置信息
- [x] 评定纯净度等级（优秀/良好/一般/较差）
- [x] 智能缓存（只检测新增可用节点）

### 2.4 数据持久化

**需求描述**: 将检测结果永久保存，刷新页面后仍可查看

**用户故事**:
- 作为用户，我希望检测结果能够永久保存，以便下次访问时查看历史数据
- 作为用户，我希望导入新节点时能够保留旧节点的检测历史
- 作为用户，我希望检测结果保存失败时能够手动重试

**验收标准**:
- [x] 检测结果自动保存到JSON文件
- [x] 保存失败时自动重试（最多3次，递增延迟）
- [x] 提供手动保存按钮作为补救措施
- [x] 智能合并算法（新节点添加，旧节点保留历史）
- [x] 刷新页面后自动加载历史数据
- [x] 显示最后检测时间

### 2.5 界面优化功能

**需求描述**: 提供友好的用户界面和交互体验

**用户故事**:
- 作为用户，我希望能够按不同维度排序节点，以便找到最合适的节点
- 作为用户，我希望能够按国家筛选节点，以便选择特定地区的节点
- 作为用户，我希望节点列表能够流畅滚动，以便查看大量节点
- 作为用户，我希望页面能够自动刷新，以便获取最新数据

**验收标准**:
- [x] 可滚动节点列表（固定10行高度，表头固定）
- [x] 智能排序（按延迟/名称/国家/纯净度）
- [x] 国家筛选（识别40+国家，显示节点数量）
- [x] 自动刷新（每30秒检查更新）
- [x] 赛博朋克科幻风格
- [x] 50+种流畅动画效果

### 2.6 节点导出功能

**需求描述**: 导出选中的节点为YAML配置文件

**用户故事**:
- 作为用户，我希望能够导出选中的节点，以便在Clash中使用
- 作为用户，我希望导出的配置文件格式正确，可以直接使用

**验收标准**:
- [x] 支持选择多个节点导出
- [x] 生成标准Clash配置文件
- [x] 自动命名文件（包含日期）
- [x] 一键下载到本地

### 2.7 自动更新系统

**需求描述**: 定时自动从机场聚合器获取最新节点

**用户故事**:
- 作为用户，我希望系统能够自动更新节点，无需手动操作
- 作为用户，我希望能够查看更新历史，了解节点变化情况

**验收标准**:
- [x] Cron定时任务（每6小时执行）
- [x] 自动下载最新节点
- [x] 智能合并更新（保留历史数据）
- [x] 更新日志记录
- [x] Web界面查看更新历史

## 3. 非功能需求

### 3.1 性能需求
- 页面加载时间 < 1秒
- 节点列表渲染 < 100ms
- 滚动帧率 ≥ 60fps
- 并发检测效率 ~3秒/节点
- 支持至少100个节点流畅显示

### 3.2 兼容性需求
- 支持Chrome/Edge浏览器
- 支持Firefox浏览器
- 支持Safari浏览器
- 支持移动端浏览器
- 响应式设计

### 3.3 安全需求
- 所有API调用使用HTTPS
- 文件权限正确设置（目录775，文件664）
- 防止SQL注入（使用JSON存储）
- 防止XSS攻击（输入验证）

### 3.4 可维护性需求
- 代码注释清晰（中文）
- 模块化设计
- 完整的文档体系
- 错误日志记录

## 5. 数据需求

### 5.1 节点数据结构
```json
{
  "node_hash": "唯一标识",
  "type": "协议类型",
  "name": "节点名称",
  "server": "服务器地址",
  "port": "端口",
  "uuid": "UUID（vless/vmess）",
  "password": "密码（trojan/ss/ssr）",
  "country": "国家/地区",
  "available": "可用性（0/1/null）",
  "latency": "延迟（毫秒）",
  "real_ip": "真实IP",
  "ip_purity_score": "纯净度评分（0-100）",
  "purity": "纯净度等级",
  "last_check_time": "最后检测时间"
}
```

### 5.2 存储位置
- 节点数据：`Projects/NodeLocalChecker/data/nodes.json`
- 更新日志：`Projects/NodeLocalChecker/logs/update_*.log`
- Clash配置：`Projects/NodeLocalChecker/yamls/config_clash_*.yaml`

## 8. 风险与限制

### 8.1 已知限制
1. **国家识别准确度**
   - 34.1%节点识别为"其他"
   - 原因：节点名称不规范
   - 影响：轻微，不影响使用

2. **自动刷新延迟**
   - 最多30秒延迟
   - 原因：定时器间隔设置
   - 影响：轻微

3. **大量节点性能**
   - 超过1000个节点可能卡顿
   - 原因：DOM渲染压力
   - 当前82个节点无影响

### 8.2 技术风险
- Clash核心依赖：需要正确安装和配置
- 第三方API依赖：IP纯净度检测依赖外部API
- 文件权限问题：需要正确的读写权限
